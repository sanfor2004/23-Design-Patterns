# Scheda rapida

[Catalogo dei pattern](README.it.md)

Un aiuto alla scelta per tutti i 23 pattern. Sapere quando evitarli conta quanto sapere quando usarli.

| Catalogo dei pattern | Significato semplice | Categoria | Usalo quando | Evitalo quando | Per ricordare |
| --- | --- | --- | --- | --- | --- |
| [Abstract Factory](creational/abstract-factory/README.it.md) | Crea una famiglia di Object compatibili | Creational Pattern | Usalo quando più tipi di prodotto devono cambiare insieme senza esporre le concrete class al client. | Evitalo per un solo prodotto stabile o quando le combinazioni indipendenti sono desiderabili. | Una fabbrica, un insieme coordinato. |
| [Builder](creational/builder/README.it.md) | Costruisci un Object per passi chiari | Creational Pattern | Usalo con molte opzioni indipendenti o un punto significativo di validazione. | Evitalo per due parametri evidenti: un piccolo aggregato può bastare. | Scegli i passi, poi costruisci. |
| [Factory Method](creational/factory-method/README.it.md) | Lascia scegliere a una subclass quale Object creare nel flusso comune | Creational Pattern | Usalo quando un flusso già basato sull'inheritance richiede un punto di creazione estensibile. | Evitalo se basta passare un Sender pronto a una function. | Conserva il flusso, personalizza la creazione. |
| [Prototype](creational/prototype/README.it.md) | Crea un nuovo Object copiandone uno configurato | Creational Pattern | Usalo quando object esistenti contengono configurazioni utili e il client non deve ricostruire i concrete type. | Evitalo quando una normale copia per valore esprime già bene il bisogno. | Copia la configurazione, non l'identità. |
| [Singleton](creational/singleton/README.it.md) | Fornisci una sola instance condivisa con accesso globale | Creational Pattern | Consideralo solo se l'unicità è davvero un vincolo del processo e il lifetime è appropriato. | Evitalo per rendere comodo l'accesso alle dependency: passa un reference esplicito per isolare i test. | Una sola instance può creare molti problemi. |
| [Adapter](structural/adapter/README.it.md) | Adatta una Interface esistente a un’altra | Structural Pattern | Usalo al confine con un'API che non puoi o non conviene modificare. | Evitalo se controlli entrambe le parti e puoi uniformare facilmente il contratto. | Traduci al confine. |
| [Bridge](structural/bridge/README.it.md) | Lascia variare separatamente due aspetti | Structural Pattern | Usalo se due assi di variazione produrrebbero un prodotto cartesiano di subclass. | Evitalo con una sola variazione semplice già gestibile da un parametro. | Due assi, un collegamento. |
| [Composite](structural/composite/README.it.md) | Usa la stessa operazione per un elemento o un albero di elementi | Structural Pattern | Usalo per veri alberi parte-tutto con un'operazione utile sia alle foglie sia ai gruppi. | Evitalo per liste piatte o grafi con condivisioni e cicli: l'ownership ad albero sarebbe scorretta. | Il gruppo risponde come un elemento. |
| [Decorator](structural/decorator/README.it.md) | Aggiungi behavior avvolgendo un Object | Structural Pattern | Usalo per behavior facoltativi e componibili che rispettano il contratto originale. | Evitalo se bastano una lista di ingredienti e una somma; qui lo scopo è mostrare la struttura. | Stesso contratto, uno strato in più. |
| [Facade](structural/facade/README.it.md) | Offri un ingresso semplice a un sottosistema complesso | Structural Pattern | Usala quando molti client richiedono lo stesso sottoinsieme utile di un sistema complesso. | Evitala per un semplice inoltro che non semplifica nulla. | Un ingresso per più servizi. |
| [Flyweight](structural/flyweight/README.it.md) | Condividi dati immutable ripetuti | Structural Pattern | Usalo dopo aver misurato una duplicazione significativa di dati immutabili. | Evitalo per pochi dati, state individuale mutabile o ricerche più costose del risparmio. | Condividi la forma, separa la posizione. |
| [Proxy](structural/proxy/README.it.md) | Controlla l’accesso tramite un Object sostitutivo | Structural Pattern | Usalo per lazy initialization, autorizzazione o accesso remoto con un'interface stabile. | Evitalo se costruire direttamente costa poco e la politica di accesso non serve. | Un sostituto controlla l'accesso. |
| [Chain of Responsibility](behavioral/chain-of-responsibility/README.it.md) | Passa una richiesta tra Handler che possono fermarla o proseguire | Behavioral Pattern | Usala quando ordine e composition dei controlli devono variare indipendentemente. | Evitala per due controlli fissi in un solo punto: l'espressione iniziale è più chiara. | Gestisci oppure passa avanti. |
| [Command](behavioral/command/README.it.md) | Conserva un’azione in un Object | Behavioral Pattern | Usalo per azioni differite, code, macro e annullamento. | Evitalo per una chiamata isolata senza necessità di memorizzare o pianificare l'intento. | Un'azione da conservare. |
| [Interpreter](behavioral/interpreter/README.it.md) | Rappresenta le regole di un piccolo linguaggio con un expression tree | Behavioral Pattern | Usalo per grammatiche piccole e stabili con un albero utile da costruire e ispezionare. | Evitalo per linguaggi grandi che richiedono parsing robusto, diagnostica e ottimizzazione. | I nodi grammaticali danno significato. |
| [Iterator](behavioral/iterator/README.it.md) | Scorri una raccolta senza esporne la memoria interna | Behavioral Pattern | Preferisci iterator standard o ranges per esporre il percorso senza esporre lo storage. | Evita un iterator personalizzato quando bastano const_iterator esistenti o un range; qui è didattico. | Percorri i dati senza aprire il container. |
| [Mediator](behavioral/mediator/README.it.md) | Raccogli le regole di coordinamento in un Object | Behavioral Pattern | Usalo quando le interazioni fra più pari diventano intricate. | Evitalo per un semplice callback o in assenza di regole di coordinazione. | I colleghi passano dal coordinatore. |
| [Memento](behavioral/memento/README.it.md) | Salva lo State e ripristinalo più tardi | Behavioral Pattern | Usalo per checkpoint di cui l'Originator sa definire uno state consistente. | Evitalo per state enormi, risorse non ripristinabili o quando operazioni inverse costano meno. | Ricorda lo state senza esporlo. |
| [Observer](behavioral/observer/README.it.md) | Avvisa chi è iscritto quando qualcosa cambia | Behavioral Pattern | Usalo quando un cambiamento interessa più consumatori registrati indipendentemente. | Evitalo per una sola dependency fissa o quando serve consistenza transazionale rigorosa. | Pubblica il cambiamento, lascia reagire. |
| [State](behavioral/state/README.it.md) | Lascia che lo State corrente decida la risposta | Behavioral Pattern | Usalo quando behavior e transizioni dipendenti dallo state si disperdono fra operazioni. | Evitalo per un toggle banale o una piccola tabella enum leggibile. | Stesso event, state diverso, risposta diversa. |
| [Strategy](behavioral/strategy/README.it.md) | Usa Algorithm diversi per lo stesso compito | Behavioral Pattern | Usala quando gli algorithm variano indipendentemente e il client deve scegliere una politica. | Evitala per un algorithm stabile o una condizione leggibile senza vera pressione di estensione. | Stesso compito, algorithm a scelta. |
| [Template Method](behavioral/template-method/README.it.md) | Mantieni la sequenza e lascia alle subclass alcuni passi | Behavioral Pattern | Usalo per una sequenza stabile con pochi punti di estensione ben definiti. | Evitalo se i passi vanno riordinati a runtime o la composition chiarisce meglio le dependency. | Conserva la ricetta, varia i passi. |
| [Visitor](behavioral/visitor/README.it.md) | Aggiungi operazioni fuori da un insieme stabile di tipi | Behavioral Pattern | Usalo con tipi stabili e operazioni nuove frequenti. | Evitalo se aumentano spesso i tipi o esporre dettagli rompe l'encapsulation. | Tipi stabili, operazioni nuove. |
